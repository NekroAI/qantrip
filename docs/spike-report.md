# 阶段 1 可行性报告：macOS 插入链路 Spike

**日期：** 2026-10-17
**结论：** 通过。macOS 采用"Rust 核心 + UniFFI + Swift（AppKit / SwiftUI）原生外壳"路线（D6），进入阶段 2。
**环境：** macOS 27.0.1，Apple Silicon，仅 Command Line Tools（无 Xcode）。

## 实现要点（供阶段 2 沿用）

- **面板：** `NSPanel`，样式 `[.borderless, .nonactivatingPanel]`，`.nonactivatingPanel` 必须在初始化时设置；重写 `canBecomeKey`。启动时预先布局并离屏渲染一次，消除冷启动开销。
- **按键处理：** 输入框用 AppKit `NSTextField`，经 `control(_:textView:doCommandBy:)` 处理 Enter、方向键、Tab、Esc。输入法组字期间系统不会把这些命令交给我们。
- **粘贴：** 写入时附加 `org.nspasteboard.TransientType` / `ConcealedType` / `AutoGeneratedType`；⌘V 的键码按当前 ASCII 键盘布局解析（兼容 Dvorak 等布局）；用 `changeCount` 判断恢复前剪贴板是否被改动。
- **不可靠的读数：** non-activating 面板下 `NSApp.isActive` 会报 true，但系统视角并未切换。判断前台应用一律用 `NSWorkspace.frontmostApplication`。
- **开发签名：** 专用钥匙串 + `Qantrip Dev` 证书（`scripts/dev-cert.sh`），不改动登录钥匙串。

## 已知限制

- **Claude Code 折叠长粘贴：** 超过一定长度的粘贴显示为 `[Pasted text #1 +7 lines]` 占位符，实际发送完整内容。这是目标应用自身的行为；改为逐字键入会带来误提交风险，因此不绕开，改为在 Qantrip 侧提供插入前预览。
- **剪贴板管理器：** 只验证了 Maccy。Raycast、Paste、Windows 剪贴板历史未验证。
- **Spike 调试钩子：** `debugHooks` 允许本机其他进程借用本应用的辅助功能权限插入文本，正式版本必须移除。

## 测试方法

- `tests/spike/run_insert_tests.py`：探针应用 PasteProbe 接收粘贴并写入文件，与 Rust 核心的渲染结果逐字比对；`pbtool` 比对剪贴板全部类型的哈希；直接只读查询 Maccy 的 SQLite 历史。
- `tests/spike/bp-probe.py`：在终端中开启 bracketed paste，原样记录收到的字节。
- 埋点日志：`~/Library/Logs/Qantrip/spike.jsonl`（只记录时长、字符数等指标，不记录 Prompt 正文）。
