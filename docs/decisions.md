## 已做决定

### D1 暂不购买 Apple Developer ID（2026-10-17）

- **决定：** 项目成型后再考虑购买。
- **影响：** 未签名应用的辅助功能（TCC）授权与签名身份绑定，ad-hoc 签名每次构建都会变化，导致每次更新都要重新授权。
- **对策（已写入 PRD 12.2）：**
  - 用一个固定的自签名代码签名证书签名所有发布版本。
  - 提供不需要任何权限的"只复制"降级模式（PRD 7.2）。
  - 文档如实说明 Gatekeeper "仍要打开"的步骤。
  - 将来迁移到 Developer ID 时，用户需要重新授权一次。

### D2 Cloudflare 端到端加密同步保留在 P1（2026-10-17）

- **评审意见：** 建议推迟到 P2，P0/P1 先用纯文件 + Git / 网盘同步，因为 E2EE 客户端（密钥层级、配对、轮换、冲突）工作量大。
- **负责人决定：** 保留。理由是团队已有多个 Cloudflare 项目，服务端可以改造复用。
- **评审补充（已写入 PRD 9.2）：** 服务端确实可以复用，但主要工作量在客户端。因此 P1 拆成"同步服务端"和"E2EE 客户端"两个工作项分别估算。
- **可复用来源：** `nekro-nxt-community` 项目的 `apps/site`（Hono + D1 + React Router，部署在 Workers 上；数据层是原生 SQL 加一层很薄的封装，并未使用 Drizzle——2026-10-17 核对更正）

  | 文件 / 表 | 可复用为 |
  |---|---|
  | `server/oauth.ts`（PKCE 授权码流程）、`oauth_codes` 表 | 桌面端通过浏览器回调登录 |
  | `instance_grants` 表（access/refresh 令牌哈希轮换、`revoked_at`） | 设备授权与撤销 |
  | `wrangler.jsonc` 中的 `WRITE_LIMITER`、`audit_log` 表 | 限流、审计 |
  | `migrations/`（wrangler d1 migrations） | 迁移体系 |

- **禁止复用：** `server/crypto.ts`。它用服务端环境变量 `CONFIG_ENCRYPTION_KEY` 派生密钥加解密，服务端能解密，违反 E2EE 要求。
- 其他 Cloudflare 参考项目：`nekro-cloud`、`nekro-endpoint`（同一套 Hono/D1/Drizzle 技术栈）。

### D3 AI 配置由用户自行配置，可选加密同步（2026-10-17）

- **评审意见：** 建议不内置 AI 客户端，改为提供 CLI / MCP server，让用户已有的 AI 编程代理直接编辑模板。
- **负责人决定：** 保留内置 AI 编辑。配置由用户自己填写，并可选择和其他数据一起加密同步。
- **落地（PRD 6.3 / 6.4 / 9.5 / 9.7）：**
  - 每个供应商配置单独设置同步开关，默认关闭。
  - API Key 在本机存入系统安全存储；同步时走 E2EE。
  - Base URL 支持"同步默认值 + 本机覆盖"。
  - 撤销设备时，提示用户到供应商处作废已同步的 Key。
  - 只实现 OpenAI 兼容和 Anthropic 两种协议。
- CLI / MCP 作为补充，仍列在待决事项中。

- **仓库：** `NekroAI/qantrip`
- **由来：** Q + cantrip（D&D 中不耗资源、可随手施放的"戏法"）。Q 呼应唤起快捷键，Prompt 在中文圈常被称为"咒语"。
- **考虑过的其他名字：**
  - Cantrip / Incant / Quickcast（不加 Nekro 前缀）
  - Nekro Grimoire / Scroll / Rune / Chant / Pounce
  - Nekro Quoth（备选第二）、Nekro Qast
  - 否决：Quiver（已有 3.6k★ 项目和同名 Mac 应用）、Summon / Mantra / Sigil（过于常见）、PromptKey（已被竞品使用）

### D5 默认快捷键方向：Q 系（2026-10-17，具体组合待验证）

- **负责人意向：** 结合 Ctrl+Q 设计，与产品名形成联动。
- **评审意见：** Windows / Linux 上 `Ctrl+Q` 在浏览器和多数 GTK/Qt 应用中是"退出"，热键注册失败时会直接关掉用户的应用。
- **当前方案（PRD 3.1）：** macOS 用 `⌃Q`，Windows / Linux 用 `Alt+Q`；不用 `Ctrl+Alt+Q`（等同 AltGr，部分布局用它输入 `@`）。用户可以改回 `Ctrl+Q`，此时提示风险。（Windows 已由 D33、Linux 已由 D37 改为 `Ctrl+Q`。）
- **待办：** 原型阶段做三平台冲突实测后定稿。**负责人尚未明确确认这一方案。**

### D6 技术路线：各平台原生外壳 + 共享 Rust 核心，不以 Tauri 为主框架（2026-10-17）

- **负责人决定：** 以体验为导向，允许各平台原生实现；负责人不倾向 Tauri。
- **架构：** Rust 核心（输入语法、渲染、存储，后续同步与加密）经 UniFFI 暴露给各平台外壳。macOS 外壳用 Swift（AppKit + SwiftUI），SwiftPM 构建、脚本组装 `.app`，不依赖完整 Xcode。Windows / Linux 外壳技术待定（候选：C# + uniffi-bindgen-cs、windows-rs、GTK4）。（后由 D32、D37 确定。）
- **评审意见：** Tauri 对本项目的主要价值只是三平台共用管理类界面（模板库、编辑器、设置）。如果日后三份原生管理界面成本过高，可以在原生窗口中嵌入 WebView 只承载这些页面，届时再议。
- 取代 PRD 10.2 中"Tauri 2 作为重点候选"的表述。

### D9 面板输入法策略：唤起时切到英文（2026-10-17）

- **问题：** 中文输入法状态下唤起面板，命令词会进入拼音组字，必须删掉、切换输入法后重输。
- **负责人决定：** 打开面板时自动切到英文（ASCII）输入源，关闭时恢复原输入法；输入中文附加文本时由用户手动切换。设置中可关闭此行为。
- **否决：** 进入附加文本区时自动切回中文（无法提前判断用户要输入参数还是附加文本，误判代价高）；保留中文输入法并识别拼音字母（空格会被输入法当作选词）。

### D13 ⌘↩ 展开粘贴（2026-10-17）

- **来源：** 负责人指出 Claude Code 中连续粘贴两次会把折叠占位符展开为完整内容。
- **决定：** ⌘↩ 确认时连续发送两次 ⌘V，普通 ↩ 只粘贴一次。设置中可关闭，两次粘贴的间隔可调。
- 不做自动识别：Claude Code 运行在终端内，无法可靠判断；在其他应用中两次粘贴会插入重复内容，所以必须由用户显式触发。
- **Claude Code 的实际规则**（2026-10-17 核对 2.1.285 的源码与公开资料）：
  - 折叠：粘贴内容超过 800 字符，或换行符超过 2 个（终端很矮时阈值更低）。另一种输入界面（agents 视图）的字符阈值为 4096。
  - 展开：再次粘贴与**最近一次**粘贴完全相同的内容（`\r\n` 统一为 `\n` 后比较），且内容不超过 100,000 字符。
  - 处理粘贴是异步的，第二次粘贴需要间隔；间隔默认值待实测。
- **据此：** 渲染结果不超过 800 字符且换行不超过 2 个时，⌘↩ 只粘贴一次，避免插入重复文本。阈值属于 Claude Code 的内部实现，版本变化时需要重新核对。

### D14 首屏与排序：最近施放 + 常用 + 全部，按应用区分（2026-10-17）

- **负责人反馈：** 打开面板、尚未输入时需要合适的首屏，建议按最近使用和使用频次排序。
- **决定：**
  - 首屏分三段：最近施放（含参数的完整调用，一键重放）、常用（frecency：频次 + 时间衰减）、全部模板（按分类）。新用户没有历史时，以"试试看"示例代替最近施放。
  - 排序结合当前前台应用的使用习惯（终端里常用 review、浏览器里常用 zh），作为 PRD 7.3 上下文感知的轻量起步，不需要额外权限。
  - 输入后的匹配结果在同一层级内按 frecency 排序；使用数据在面板打开时取快照（语法规范 §3）。
- **隐私：** 使用记录只存在本机，不记录附加文本（附加文本可能含敏感内容），也不记录渲染后的 Prompt。

### D15 动效：服务于"看见 Prompt 被组装"（2026-10-17）

- **负责人反馈：** 应用"不够活，没有任何动效"。
- **决定：** 唤起弹性入场与候选错落出现、候选重排滑动与选中高亮滑移、命令锁定时图标反馈、参数标签弹跳、预览变化片段闪光后淡成高亮、插入时快照上浮淡出加星光粒子、输入错误时抖动。
- **约束：** 每个动效不超过约 200ms，可被打断，不阻塞输入；系统开启"减少动态效果"时降级。

### D16 鼠标操作：改写命令行文本（2026-10-17）

- **负责人反馈：** 鼠标无法点选，部分用户会用鼠标组织提示。
- **决定：** 候选可单击（等同 Tab）、双击模板直接插入；参数标签可点击（开关切换、单选/多选弹出菜单、文本/数字定位到输入位置）；底栏按钮可点击。
- 所有鼠标操作都改写命令行文本，命令行是唯一的状态来源，键盘与鼠标结果一致。改写时可能把用户的写法整理为规范形式。

### D17 字体：方案 B「现代工坊」（2026-10-17）

- **负责人反馈：** 应用需要更有质感、辨识度更高的字体，不止一种。
- **决定：** 按角色分配字体：
  - 命令行与代码元素（模板名、参数、规范形式）：Monaspace Neon（GitHub Next，变量字体）。
  - 模板标题等少量展示性大字：Fraunces（柔和衬线变量字体，SOFT / WONK 轴）。
  - 预览正文与界面小字：系统字体（苹方 / SF），保证可读性与原生感。
- **否决：** 方案 A（Maple Mono + Instrument Serif + 霞鹜文楷）、方案 C（Monaspace Radon + 霞鹜文楷）。两者都需要内置约 25MB 的中文字体。
- 两款字体均为 SIL OFL 1.1，随应用分发，许可证放在 `apps/macos/Resources/Fonts/`。应用体积约增加 1.5MB。

### D18 剪贴板恢复标记为临时内容，回车被阻止时不发声（2026-10-17）

- **来源：** 负责人体验时持续听到声音，并担心剪贴板受影响。
- **排查：** 在 Mini 上监听系统音频日志：普通复制、插入（含展开粘贴）都不发声，唯一的声音是回车被阻止时的 `NSBeep`。负责人通过 UU 远程访问，剪贴板变化（写入 Prompt、恢复原内容）会同步到控制端 Mac，这是远程桌面的副作用。
- **发现：** 恢复原剪贴板会被剪贴板管理器当作一次新的复制（Maccy 中同一条记录计数累加到 29）。
- **决定：** 恢复时为原内容附加 `org.nspasteboard.TransientType`（不加 ConcealedType）；回车被阻止时只保留视觉反馈。回归测试新增"恢复不增加 Maccy 复制计数"。
- **已知限制：** 远程桌面或 Universal Clipboard 等同步机制只传纯文本，临时标记无法跨设备保留。以后可评估通过辅助功能 API 直接写入文本框、完全绕开剪贴板（仅部分应用支持）。

### D22 打包与发布（2026-10-17）

- **签名：** 新建发布证书「Nekro Qantrip Release」（自签名，有效期至 2046 年）。p12 与密码存入仓库 Actions Secrets（`MACOS_SIGNING_P12` / `MACOS_SIGNING_PASSWORD`），负责人另行离线备份；不进入 git。开发构建继续使用本机的「Qantrip Dev」证书。

### D23 云服务与官网：同一个 Worker（2026-10-17）

- **形态：** 一个 Worker「nekro-qantrip」同时承载官网（React Router 服务端渲染）、账号页面与 `/api/v1/*`（Hono），数据在 D1，安装包镜像在 R2；另有 staging 环境。沿用 `nekro-nxt-community` 的入口分流、GitHub 登录、桌面端 PKCE 授权、令牌哈希轮换、限流与审计；不复用其 `server/crypto.ts`（D2）。
- **域名：** `qantrip.nekro.ai`，staging 为 `qantrip-staging.nekro.ai`。
- **上线：** 官网公开；下载与更新接口先不公开（下载页显示即将开放，R2 镜像与版本接口由开关控制）。

### D31 指令模式 v1（2026-10-18，细化 D26）

- **触发：** 面板输入以 `/` 开头即进入指令模式（模板名不能以 `/` 开头，不冲突）。指令与模板命令共用同一套高亮、补全、预览与诊断。
- **指令：** `/new <名称> [正文]` 新建；`/edit <名称>` 在模板库中打开；`/dup <名称> <新名称>` 复制（常用于改写内置模板）；`/alias <名称> <别名>` 添加别名；`/rm <名称>` 删除（第二次回车才执行，可撤销）。只作用于用户模板目录；内置模板只能 `/dup` 或 `/edit`（等同于自定义）。
- **参数占位符：** 正文中 `{名}` 生成文本参数，`{名:a|b|c}` 生成单选参数（第一个为默认），其余原样保留；生成的是普通模板文件，复杂参数仍在模板库里编辑。
- **正文来源：** `/new 名称` 不写正文时使用剪贴板中的文字，预览中先展示将要创建的模板。
- **补充（同日，负责人要求"把指令一并做完"）：** 增加应用操作指令 `/sync`、`/settings`、`/library [名称]`、`/lang auto|zh|en`（内置模板语言）；核心通过 `CommandOutcome.action` 告知外壳执行，macOS 与 Windows 均已接入。

### D34 删除对所有模板生效，内置模板可恢复（2026-10-18）

- **背景：** 内置模板占用了开发者常用的命令拼写（如 `r`、`ci`、`test`）。负责人要求删除对所有模板生效，内置模板删除后应能以符合直觉的方式恢复。

### D36 回车与 Tab 职责分开（2026-10-18）

- **背景：** 负责人反馈输入一部分后回车常常只是补全、要再按一次才插入，与 Tab 重复。
- **决定：** 回车 = 按当前解析结果确认（插入右侧预览显示的内容，模糊匹配也直接插入高亮项），从不改写输入；Tab = 补全（高亮候选、灰字、或缺失必填参数的修正）。无法插入时回车不执行并说明原因。指令模式中无歧义前缀回车即执行。取代此前"模糊匹配第一次回车只补全"的规则；防误插入改由预览承担（回车前即可看到将插入的模板与内容）。

### D37 Linux 外壳：Rust + GTK4 / libadwaita（2026-10-18）

- **负责人决定：**
  1. **界面：** Rust + GTK4 / libadwaita（gtk4-rs、libadwaita-rs），放在 `apps/linux/`（独立 Cargo 项目），直接依赖 `core` crate，不经过 FFI。理由：与核心同一语言，省去绑定层；GTK 是 GNOME 原生、在 KDE 上同样可用的主流工具包，输入法（IBus / Fcitx5）与门户集成成熟。遵循 D6 各平台原生外壳。
  2. **支持范围：** GNOME（Wayland）、KDE Plasma（Wayland）、X11 会话完整支持并实测；Sway / Hyprland 等 wlroots 桌面尽力支持（自动粘贴用 wtype），不作保证。
  3. **全局快捷键：** Wayland 用 xdg-desktop-portal GlobalShortcuts；X11 用 XGrabKey；都不可用时引导用户在系统设置中添加自定义快捷键，绑定到 `qantrip toggle`（单实例：GApplication 经 D-Bus 把命令转交给运行中的实例）。
  4. **Wayland 自动粘贴：** RemoteDesktop 门户请求授权，恢复令牌持久化（之后不再询问），模拟粘贴键；不授权或桌面不支持时只复制并提示按 Ctrl+V。X11 用 XTest。终端类应用（按 WM_CLASS / app_id 识别）用 Ctrl+Shift+V。保留不需要任何权限的“只复制”模式。
  5. **默认唤起快捷键 Ctrl+Q**（取代 D5 中 Linux 用 Alt+Q 的方案），与 macOS / Windows 及宣传一致，可修改；排除的应用（D35）在 Linux 上实现：X11 按活动窗口的 WM_CLASS，Wayland 尽力而为，取不到时在界面中说明。
- **实现要点（实测后确定）：**
  - **面板窗口：** Wayland 下应用不能指定窗口位置（GNOME 会把新窗口放在左上角），面板窗口最大化且透明，卡片放在屏幕上方约 1/3 处，点击卡片外部关闭；全屏窗口在 GNOME 中会被铺上黑色背景，因此用最大化；KWin 不会最大化不可调整大小的窗口，所以窗口设为可调整大小。X11 下为普通无边框窗口，用 `_NET_WM_STATE` 置顶、不进任务栏，放到鼠标所在屏幕。不使用 layer-shell（GNOME 不支持）。
  - **激活：** 门户 Activated 信号与 GApplication 转发命令行时附带的激活令牌由 GTK 使用，GNOME 与 KDE 上面板都能取得焦点；从没有令牌的进程（如 SSH）执行 `qantrip toggle` 时 GNOME 不给焦点，从 GNOME 自定义快捷键执行则正常。
  - **GlobalShortcuts：** GNOME 50 与 KDE Plasma 6.6 均弹出一次确认对话框，之后由系统记住（重启应用不再询问）。门户返回的组合键说明格式不同（GNOME 为 `Press <Control>q`），界面统一显示为 `Ctrl+Q`。修改快捷键在系统设置中进行（门户 v2 时直接打开系统的配置界面；KDE 为 v2，GNOME 为 v1）。主机应用需要先经 `org.freedesktop.host.portal.Registry` 登记应用 ID（xdg-desktop-portal 1.19+），并且系统中要有同名 .desktop 文件；AppImage 首次运行时自行写入 `~/.local/share/applications`。
  - **RemoteDesktop：** GNOME 在会话存在期间顶栏一直显示远程控制指示，因此每次粘贴临时建立会话（约 60ms），发送按键后立即关闭；KDE 每建立一次会话都弹出“远程控制会话已开始”通知，因此保持一个会话直到退出。恢复令牌一次性使用、每次更新，按桌面分别保存（`~/.local/state/qantrip/`，0600）；令牌失效时系统重新询问，确认后粘贴照常完成。
  - **粘贴按键：** GNOME（Wayland）不向应用公开前台窗口，识别不出终端，此时用 Shift+Insert，并同时写入 PRIMARY 选区：GTK、Qt、浏览器与 VTE / Konsole 等终端都会粘贴。设置中可固定为 Ctrl+V / Ctrl+Shift+V / Shift+Insert。
  - **剪贴板：** X11 下唤起面板时备份剪贴板全部格式，粘贴 500ms 后若剪贴板仍是我们写入的内容则恢复（与 macOS / Windows 相同）。Wayland 下应用失去焦点后不能再写剪贴板，因此不恢复，Prompt 留在剪贴板中（已知限制）。写入时附加 `x-kde-passwordManagerHint: secret`，Klipper 等不记录（相当于 macOS 的 TransientType）。
  - **前台应用：** X11 读取 `_NET_ACTIVE_WINDOW` 与 `WM_CLASS`；KDE Plasma（Wayland）加载一个 KWin 脚本，窗口激活时经 D-Bus 回调 `resourceClass`（app_id），退出时卸载；GNOME（Wayland）取不到，排除列表无效并在设置中说明。Wayland 下快捷键由系统持有，按键不能像 X11（XUngrabKey）那样原样交给被排除的应用，只是不打开面板。
  - **输入法（D9）：** Fcitx5 经 D-Bus `Controller1.Deactivate` 让面板输入框回到英文（状态按输入上下文保存，原应用不受影响）；IBus 的引擎是全局的，面板打开时切到对应的 xkb 引擎、关闭时切回（GNOME 的输入源指示器随之更新）。组字期间不解析、不处理回车与方向键；组字结束时补发一次解析。GNOME 用 Super+空格切换输入源时，切换器会短暂取得焦点，面板的失焦关闭因此延迟约 0.2 秒再确认。
  - **渲染器：** 默认使用 GTK 的 Cairo 渲染器（未设置 `GSK_RENDERER` 时）：没有 GPU 的机器上 GL / Vulkan 渲染器经软件实现常驻 300MB 以上，Cairo 约 140–200MB；启动其他程序时去掉这个环境变量。
  - **同步密钥：** 全部密钥合成一个 Secret Service 条目（GNOME 密钥环、KWallet），与 macOS 合成一个钥匙串条目对应；系统没有可用的 Secret Service 时回退为仅本用户可读的文件（0600），设置 › 同步中说明。一旦选定后端就固定使用，避免密钥分散。
  - **提示（HUD）：** 用桌面通知（`org.freedesktop.Notifications`，transient），不抢焦点。不能附加 `desktop-entry` 提示，也不能用低优先级：GNOME 在这两种情况下都不弹出横幅。
  - **托盘：** StatusNotifierItem（ksni）。GNOME 的 AppIndicator 扩展不按自带主题路径加载图标，改为提供像素图；没有托盘宿主时应用照常运行，从应用菜单再次打开 Qantrip 即进入模板库与设置。
  - **打包：** AppImage、.deb、.rpm（`scripts/package-linux.sh`），x86_64 与 aarch64 在 GitHub Actions 的 ubuntu-24.04 / ubuntu-24.04-arm 上构建。AppImage 不内置 GTK / libadwaita：内置后系统的输入法模块与主题、门户集成都会失效。因此三种包都要求系统提供 GTK 4.14+ 与 libadwaita 1.5+（Ubuntu 24.04、Debian 13、Fedora 40 及更新）。更新提示的“下载”按安装方式（AppImage / deb / rpm）与架构直接下载对应文件。
- **验证：** 在 Ubuntu 26.04 ARM64 虚拟机（GNOME 50、KDE Plasma 6.6，含 Plasma X11 会话，IBus 智能拼音与 Fcitx5 拼音）中实测；同步登录需要浏览器中的 GitHub 授权，留给负责人。
- **调试钩子：** 与 macOS 的 QANTRIP_DEBUG_HOOKS 对应，只编译进 debug 构建且打开 `debug-hooks` 特性时、运行中的实例以 `QANTRIP_DEBUG_HOOKS=1` 启动才生效（`qantrip debug …`），release 构建不包含。

## 评审中提出且已写入 PRD 的要点（v0.2）

- 输入语法独立成规范，定义位置参数、附加文本、全角规范化、匹配分层和 Enter 语义（`docs/input-grammar.md`）。
- 插入用"剪贴板 + 粘贴"，不逐字键入；剪贴板备份、临时标记、恢复；Windows UIPI 降级；无权限降级模式。
- 模板渲染用成熟引擎（MiniJinja 类）+ 声明式参数 schema，不自研 DSL，渲染在沙箱中执行。
- E2EE：服务端记录 ID 随机生成，元数据全部加密；用成熟密码库；采用 Vault Key / 设备密钥对 / 恢复密钥三层；配对防中间人；提供不依赖 OAuth 的自托管认证。
- 冲突按单条记录检测并保留双方版本，首版不引入 CRDT。
- Linux：首版承诺 X11 及 KDE / GNOME 下"热键 + 复制"，Wayland 自动粘贴标注为实验性。
- 竞品：Espanso（GPL-3.0，注意许可证）、Raycast / Alfred、Claude Code slash commands、PromptKey。
